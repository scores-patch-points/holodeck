Recurring tasks

the fold can run a task on a schedule, on Cloudflare Workers. There is a version that touches nothing of yours, and a version that lives entirely in your own account.

The fold holds no Cloudflare credential. No Cloudflare OAuth, no stored token, no API access. The scheduler the fold runs can only make plain outbound HTTP calls; it cannot reach your Cloudflare account or data. This is enforced by what the code is, not by a promise — there is no grant anywhere for it to use.

Your tasks, in your hands

Sign in with GitHub to keep your tasks private to you, and the fold runs them on a one-minute heartbeat. Jobs are just HTTP calls, e.g.:

{ "name": "ping", "url": "https://example.com/health", "intervalMinutes": 5 }

The fold stores your GitHub identity and your job records. Nothing else.

Need a task to touch your own Cloudflare account?

Then run it where the credential is yours. Deploy the same scheduler into your own account, give it your own scoped API token as a secret, and the fold is not in the loop at all:

Deploy to Cloudflare
  1. The button clones the repo to your GitHub and deploys a Worker to your Cloudflare account.
  2. Add a scoped API token as a secret: npx wrangler secret put CLOUDFLARE_API_TOKEN.
  3. Give a job a cf: target; the token is substituted inside your account.

In this path the fold never sees a token, a job, or a byte of your account.

Run it from the fold

On the reading surface, one include gives you the sign-in control and the task API:

<script src="fold-scheduler-client.js"
        data-api="https://fold-scheduler.<your-subdomain>.workers.dev"
        data-ui></script>
